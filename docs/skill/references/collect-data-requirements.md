## 设备与网络拓扑

- 机器人型号：天工 2.0 PRO。
- 访问方式：先通过 `ssh tienkung` 登录上位机，再从上位机访问机器人侧主机。
- 网络关系：
  - 笔记本与上位机处在同一个无线网。
  - 上位机与机器人处在同一个有线网。
  - 上位机可以访问 `n1`、`n2`、`n3` 三台机器人主机。
- 主机角色：
  - `n1`：ROS 2 控制主机。
  - `n2`：Jetson AGX 计算单元，连接一台奥比中光相机，用于采集头部数据。
  - `n3`：Jetson AGX 计算单元，连接两台 Intel RealSense D405，用于采集手部数据。
- 机器人状态、主机信息、相机硬件和 ROS 2 话题巡检结果见 `references/robot-inspection-2026-06-08.md`。

## 采集目标

目标是在硬件和 ROS 2 通信可稳定承载的前提下，以尽可能高的频率采集 VLA 数据，并尽可能对齐以下数据：

- 三路 RGB 图像：
  - 头部相机图像。
  - 左手视角 D405 图像。
  - 右手视角 D405 图像。
- 机器人 command 数据。
- 机器人 state 数据。
- 灵巧手 command/state 数据。

核心原则：

- 优先保证数据质量和时间对齐，其次追求更高频率。
- 三路相机帧不要求完全硬同步，但每条样本应尽量取同一时间附近的最新图像帧。
- command/state 需要取最新数据，并与最终选定的图像帧时间尽可能接近。
- 状态数据不要为了凑频率而复用旧值；如果没有新的有效状态，应记录缺失或跳过样本。
- 采集频率需要根据实际可稳定输出的最低关键链路自适应调整，不能只按理论最高频率硬采。

## 一键启动脚本职责

期望提供一个 `.sh` 一键启动脚本，用于减少手动步骤。

脚本应该负责：

- 启动三台相机对应的 ROS 2 节点。
- 关闭或不启用深度话题，降低带宽和消息阻塞风险。
- 保留 RGB 图像话题、相机必要元信息话题以及采集所需的状态话题。
- 控制机器人低头，为后续采集进入合适姿态。
- 参考上位机 `/home/ubuntu/Desktop/tiangong.txt` 中关于低头控制和节点启动的说明。

脚本不应该负责：

- 直接触发天工自带的数据采集命令。
- 替代人工启动机器人已有的采集流程或数采指令。
- 在未确认安全状态时执行额外机器人运动。

## 频率与同步策略

### 频率目标

- 三路相机可能稳定在约 25-30 Hz，实际频率需要通过 `ros2 topic hz` 和采集日志确认。
- command/state 频率可能约 490-500 Hz，通常高于相机频率。
- 灵巧手 state 话题可能低于主机器人 command/state 频率，甚至可能成为最终样本频率或对齐质量的限制因素。

### 自适应规则

- 不要固定假设最终采集频率等于相机最高频率或 command/state 最高频率。
- 先分别测量三路图像、机器人 command/state、灵巧手 command/state 的稳定频率、延迟和丢帧情况。
- 以“关键数据都能稳定取到，并且时间差在可接受范围内”为有效样本标准。
- 如果灵巧手 state 频率较低或更新不稳定，最终采集频率需要向灵巧手 state 的有效更新频率适配。
- 如果相机更低频，则以相机最新帧为主锚点，并为 command/state 查找最近邻数据。
- 对机器人 state、command 和灵巧手 command/state，采样时只使用最新的未复用数据；同一条状态不应被重复写入多个新样本来伪造更高频率。
- 如果某一路相机或某个状态话题短时丢帧，采集脚本应记录该样本的时间差、缺失状态或跳过原因，避免静默写入低质量数据。

### 对齐建议

- 使用图像帧时间戳作为主要锚点；三路图像取当前采样时刻附近的最新帧。
- 对 command/state 和灵巧手数据使用最新数据或最近邻时间匹配，但必须避免重复复用同一条旧状态。
- 每条样本记录各数据源原始时间戳和相对锚点的时间差，便于后处理筛选。
- 采集频率应通过参数配置，允许在实测后从保守频率逐步上调。

## 图像尺寸与处理原则

- VLA 训练只需要 `224x224` RGB 图像。
- 优先在相机驱动、相机 launch 参数或 ROS 2 相机节点中直接配置输出 `224x224`，减少采集端 CPU/GPU 后处理开销。
- 采集脚本尽量不要做 resize、裁剪、压缩格式反复转换等额外图像处理。
- 如果相机或驱动不支持直接输出 `224x224`，不要在采集脚本中转换尺寸，直接保存相机输出的原始 RGB 数据。
- 参考现有数采项目时，需要确认当前图像是由相机直接输出，还是在采集脚本或后处理流程中转换得到。
